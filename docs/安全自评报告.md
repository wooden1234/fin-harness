# 安全自评报告

权限分级实现说明与已知风险清单

- 项目：fin-harness（财智 / 小财）
- 评估日期：2026-10-31
- 评估范围：当前仓库产品主路径，即 `POST /api/agent/query` 所走的 Harness 运行时

本报告只依据仓库中的实现、设计约束和测试入口编写。设计文档中已声明但代码尚未落地的控制，列入已知风险，不记为已实现能力。

## 1. 系统范围

财智是面向投研与客服的金融助手。用户经登录后发起对话，FastAPI 以 SSE 返回结果。产品入口只走自研 Harness：事件日志、工具菜单、调度、失败策略、上下文压缩和发布前合规检查。问财、本地财报事实、FAQ、PDF、联网搜索和计算是只读查询；记忆写入和删除是少量写操作。

本报告不把遗留的 LangGraph 编排当作对外入口。产品组合根是 `harness.runtime.product_manager`，工具菜单来自 `ToolRuntime.product()`。

## 2. 权限分级实现说明

### 2.1 身份与租户

接口使用 JWT。登录签发的令牌包含邮箱、`tenant_id` 和 `user_id`；校验时以服务端用户记录为准，不接受客户端另行传入的租户编号。用户必须处于 `active`。`tenant_id` 缺失则拒绝。实现见 `app/backend/app/core/security.py` 与 `app/backend/app/api/auth.py`。

会话按 `tenant_id`、`user_id` 和 conversation 查找或创建。同一 session 同时只允许一个 turn 持有租约，产品路径写入 PostgreSQL 表 `app.agent_session_leases`，主键为 `session_id`，默认 120 秒过期。抢占失败返回 409。

### 2.2 接口角色

在登录用户之上，管理类记忆接口再检查角色。`require_compliance_user` 只放行 `tenant_admin`、`compliance_operator`、`platform_admin`，其余返回 403。普通对话、本人记忆和会话接口只要求有效登录用户。

| 级别 | 主体 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| 未认证 | 无有效 JWT | 不能调用 Agent、会话和记忆接口 | 不能进入产品主路径 |
| 登录用户 | active 用户，租户来自服务端记录 | 本人会话、本人记忆、发起问答 | 不能调用合规管理接口 |
| 合规/租户/平台管理员 | 上述三角色之一 | 在登录能力之上访问管理记忆接口 | 角色本身不自动打开高风险工具人审 |

### 2.3 工具分级

工具注册时带有 `ToolSpec`：`risk_level`（low / medium / high / critical）、`read_only`、`requires_human_approval`、超时和重试。产品菜单由 `harness/tools/providers.py` 装配。当前问财、知识库、财务事实、计算和天气均登记为 low 且 `read_only`。记忆写入和删除不是只读，并且不可与其他工具并行。天眼查一类 MCP 工具默认 `risk_level` 为 medium，未配置环境变量时不进入菜单。

遗留执行入口 `tools/core/execution.py` 会调用 `can_use_tool`。权限列表为空时默认拒绝；名单中有该 `tool_id` 或含 `*` 才允许。`AgentRuntimeContext.from_user` 对 `admin` 角色给予 `*`，对 `user` 角色给予一份只读工具白名单，其他角色为空因而默认拒绝。这条检查位于遗留执行函数，产品主循环的 scheduler 按工具名解析后直接进入 `ToolPipeline`，不调用 `can_use_tool`。

人审开关是 `requires_human_approval`。为真时，调度器不执行 handler，写入 `approval/asked`，同批其他调用记为 `deferred_for_approval`。恢复时先确认该审批仍处于待处理，`allow` 才执行，否则写入 `denied`。同一审批不能执行两次。当前产品工具注册没有把该字段设为 True，默认值为 False。

### 2.4 数据与输出边界

FAQ 使用同一检索库，用 `domain` 枚举区分 `capital_market` 与 `corporate_finance`，检索时按该字段过滤。PDF 是另一套目录，只返回已收录且通过质量准入的文档。联网搜索提供 allowlist 与 open 两种范围，默认白名单包含交易所、监管和主流财经域名。

用户输入在进入 Agent 前做凭据检测，命中私钥、JWT、常见令牌或带标签的秘密值时返回 400，不进入工具参数。系统提示要求密钥不得进入工具参数、日志或回答。发布前 `compliance/review.py` 扫描「保证收益、稳赚、一定上涨、必涨、直接买入」，命中则用固定合规拒答替换正文。工具结果上的 `evidence_id` 留在事件日志中供追踪，不作为发布闸门。

## 3. 已知风险清单

下列事项是当前实现与设计约束之间的差距，或控制范围明确偏窄的地方。严重程度按对外部用户和数据边界的影响估计。

| 编号 | 风险 | 现状 | 建议 |
| --- | --- | --- | --- |
| R1 | 产品主路径未执行工具白名单 | 登录用户拿到的是 `ToolRuntime.product()` 全量菜单。`can_use_tool` 的用户白名单只在遗留 `execute_tool` 中生效。 | 调度前按角色过滤 `tool_id`；普通用户不暴露写工具和管理工具。 |
| R2 | 人审开关未在产品工具上打开 | 设计说明要求问财和财务事实工具审批后执行。代码默认 `requires_human_approval` 为 False，仅测试构造了 True 的例子。 | 对外部数据源或高影响查询按 `ToolSpec` 打开人审，并保持无人审批时不执行。 |
| R3 | 管理员通配权限过宽 | `from_user` 对 admin 角色设置 `permissions=("*")`。若该上下文被接到执行入口，管理员可调用全部已注册工具。 | 管理员接口与工具执行分开授权，避免用角色通配代替工具名单。 |
| R4 | 合规规则是关键词拦截 | 发布前只匹配少量禁用表达。同义荐股、承诺收益的改写可能通过。 | 保留关键词网关，并补充可回归的案例集；不把 `evidence_id` 误写成已经做了事实核对。 |
| R5 | 回答不与证据绑定 | finalization 明确不做 evidence 绑定闸门。模型可以在无引用的情况下发布正文。 | 对数字类回答增加引用或来源检查；不能通过时明确说明未查到。 |
| R6 | 联网搜索可离开白名单 | 域名边界同时支持 allowlist 和 open。open 不再受默认金融站点限制。 | 产品默认固定 allowlist；open 仅对受控调试入口开放。 |
| R7 | 外部工具凭据与结果缓存 | 问财依赖 API Key。成功的只读结果按 skill、版本和查询参数缓存在 Redis，行情类 TTL 默认 30 秒，文档类更长。 | 密钥只放环境变量；缓存键不含凭据明文；失败结果不缓存。 |
| R8 | MCP 客户端仍是有会话的旧调用方式 | `mcp/client.py` 先 initialize，再携带会话头调用工具，协议版本为 `2024-11-05`。未配置的 MCP 不注册。 | 接入新版本协议时保持按服务器配置启用，不为未配置服务暴露工具。 |

## 4. 结论

当前产品已经具备登录鉴权、租户来自服务端、会话互斥、输入凭据拦截、工具超时和错误分类、发布前关键词合规，以及只读工具与写工具的区分。权限分级的接口层是有效的。工具执行层的白名单和人审已经有代码位置，但没有接到产品主循环，因此不能写成已经对全部工具生效。

自评结论：身份和会话边界可以说明；工具权限分级只完成了元数据和遗留入口，产品菜单尚未按角色裁剪，人审默认关闭。上表 R1、R2 应在对外承诺权限分级之前补上。

## 5. 主要证据

- `app/backend/app/core/security.py`：JWT 校验与合规角色
- `app/backend/app/api/agent.py`：查询入口的凭据检测与登录依赖
- `harness/agent/postgres_leases.py`：会话租约
- `tools/core/base.py`、`harness/tools/providers.py`：工具风险、只读和人审字段
- `harness/policy.py`、`tools/core/execution.py`：遗留工具权限检查
- `agents/runtime_context.py`：按角色生成工具权限
- `harness/tools/scheduler.py`：人审暂停与恢复前的执行点
- `compliance/rules.py`、`harness/finalization/submit.py`：发布前合规
- `tools/web_domains.py`：联网搜索域名边界
- `harness/adr/00-runtime.md`：人审与证据编号的设计约束
