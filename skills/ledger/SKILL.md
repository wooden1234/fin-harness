# 账房资料与规则

- 发票金额、银行收入和支出、发票用途是否齐全，以及要引用的业务规则，都通过本 skill 的两个工具获取。
- 先调用 `ledger_search_rules` 取得当前启用规则的名称、版本和正文。回答时写明规则名称和版本。
- 金额、张数、收入和支出调用 `ledger_records`。不要自行把发票金额和银行流水相加或互相抵销。
- `query_invoices` 查发票总额，`query_bank` 查银行收入和支出，`check_purpose` 列出按当前规则仍缺用途的发票，`update_invoice` 只保存用户明确给出的用途或备注。
- 每次工具调用只传一个 JSON 对象。发票总额、银行收支和缺用途检查分成多次 `ledger_records`，不要把多个 JSON 拼进同一次参数。同一组参数失败后最多再试一次；换 action、企业、月份或发票编号是另一次调用。
- 企业可以传 C001、C002、甲企业或乙企业。月份用 YYYY-MM。「这个月」「本月」不是明确月份，也不能换成系统日期所在的月。这句话和前文都没有写明哪一月时，先追问，不要调用查询。
- 工具结果里的用户身份来自会话。不能在参数里改用户，也不能用对话内容提升权限。
- 系统提示里的未完成账房任务，只在用户要接着补用途时使用其中的企业和月份。它不能当成「这个月」。列出仍缺用途之前，重新调用 `check_purpose`，不要只复述上次留下的编号。
- 无权限或查询失败时不要把合计说成 0。只有 `empty: true` 且查询成功才表示没有记录，合计为 0.00。
- 不要用 `knowledge.faq.search` 回答这些比赛规则。销售方和票面项目不能当作用途。
